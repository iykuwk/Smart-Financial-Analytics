# Smart Financial Planning Analytics

## Case Study

---

# Project Overview

This project demonstrates the design and development of an enterprise Financial Planning & Analysis (FP&A) solution using Microsoft Power BI, Python, Excel, Power Query, and DAX.

The objective was to simulate a multinational organization's budgeting and financial planning process by generating realistic financial transactions and transforming them into an interactive executive reporting solution.

The completed solution provides finance teams with the ability to monitor financial performance, analyse variances, evaluate forecasts, and investigate transactions through a modern business intelligence dashboard.

---

# Business Problem

Finance departments often spend significant time preparing reports from multiple spreadsheets before management meetings.

Common challenges include:

- Budget overruns identified too late
- Manual budget consolidation
- Limited visibility into departmental spending
- Difficulty analysing General Ledger activity
- Poor forecasting visibility
- Time-consuming variance investigations
- Limited executive self-service reporting

These challenges delay decision-making and reduce the ability of management to respond quickly to financial risks.

# Dataset Design

A synthetic financial dataset was generated using Python to simulate real-world Financial Planning & Analysis (FP&A) activities.

The final dataset contains approximately:

| Attribute | Value |
|-----------|------:|
| Transactions | 5,000 |
| Reporting Period | January 2025 – December 2026 |
| Business Entities | 5 |
| Departments | 10 |
| Cost Centres | 10 |
| General Ledger Accounts | 14 |
| Financial Scenarios | Budget, Actual, Forecast |

The dataset includes realistic spending behaviour across departments and business entities, allowing meaningful financial analysis.

---

# Data Model

The dashboard uses a Star Schema to improve performance and simplify reporting.

## Fact Table

### Financial Transactions

Contains:

- Transaction ID
- Date
- Entity
- Department
- Cost Centre
- GL Account
- Budget
- Actual
- Forecast
- Variance
- Variance %
- Currency
- Scenario

## Dimension Tables

- Calendar
- Entities
- Departments
- Cost Centres
- GL Accounts

This modelling approach reduces redundancy while supporting efficient filtering and DAX calculations.

# Python Data Generation

Rather than using publicly available datasets, this project includes a Python-based generator that automatically creates realistic financial planning data.

The generator produces:

- Budget values
- Actual expenditure
- Forecast values
- Variance calculations
- Variance percentages
- Department-specific spending behaviour
- Entity-specific spending patterns
- Monthly seasonality
- Financial scenarios

Lookup tables are also generated automatically for:

- Business Entities
- Departments
- Cost Centres
- General Ledger Accounts

This approach makes the project repeatable and easy to extend.

---

# Financial Scenarios

Each transaction belongs to one of three reporting scenarios:

## Budget

Represents the approved planned expenditure before the reporting period.

## Actual

Represents the recorded financial performance.

## Forecast

Represents the projected financial position based on current performance and expected future activity.

These scenarios support comparison between planned, realised, and expected performance.

# Challenges Encountered

During development several technical challenges were addressed.

### Data Generation

The initial synthetic dataset produced budget, actual, and forecast values that were too similar, limiting the usefulness of variance analysis.

The Python generator was redesigned to introduce:

- Department-specific financial behaviour
- Entity spending profiles
- Monthly seasonality
- Realistic forecast calculations
- Meaningful financial variances

### Data Modelling

Relationships between the fact table and dimension tables were refined using a Star Schema to improve report performance and simplify filtering.

### Dashboard Design

Several iterations were completed to improve:

- KPI selection
- Visual layout
- Colour consistency
- Navigation
- Executive readability

These refinements resulted in a cleaner and more business-focused reporting experience.

---

# Lessons Learned

This project reinforced several best practices.

- Build a clean dimensional model before creating visuals.
- Create reusable DAX measures instead of duplicating calculations.
- Generate realistic datasets that tell a business story.
- Design dashboards for decision-making rather than displaying as many visuals as possible.
- Develop documentation alongside the technical solution.

These practices improve maintainability and make dashboards easier for end users to understand.
